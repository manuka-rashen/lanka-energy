# Lanka Energy

Explainable household electricity consumption forecasting for Sri Lanka. The application predicts the next monthly consumption in **kWh**, displays an uncertainty range, explains the model prediction, and flags a user-defined consumption limit.

Built with real RECON-SL utility records and household surveys from LIRNEasia and LECO. This is a **historical-data prototype for LECO service areas**, not a validated current nationwide forecasting service.

The public repository contains implementation, trained model and aggregate results. Household-level CSVs and per-household evaluation records are not redistributed through GitHub. The download step retrieves and verifies the original publicly released dataset from its owners.

## What is implemented

- A reproducible panel-data pipeline with six past monthly readings and optional household/appliance context.
- Date-aware masking: survey information is unavailable before its collection date.
- Comparison of persistence, moving-average, linear, XGBoost and blended forecasts.
- A selected 50% contextual XGBoost / 50% last-month forecast.
- A normalized split-conformal interval calibrated separately from model selection.
- TreeSHAP explanations, consumption-limit warnings, an API and a responsive dashboard.
- Automated integrity, leakage, input-validation and artifact replay checks.
- GitHub CI, a Dockerfile, and an Azure App Service F1 deployment template.

## Measured results

The model was selected using April–June 2024 validation targets. It was then refitted through June, calibrated on July, and frozen before testing on August–October. Entire households were excluded from fitting and selection for the separate new-household test.

| Metric | Later months, development households | Held-out households, later months |
|---|---:|---:|
| Test observations | 9,622 | 2,399 |
| Mean absolute error | 17.817 kWh | 19.281 kWh |
| Last-month baseline MAE | 17.895 kWh | 19.281 kWh |
| Root mean squared error | 39.819 kWh | 69.706 kWh |
| R² | 0.903 | 0.788 |
| Nominal 90% interval: measured coverage | 89.93% | 89.95% |

The mean-error improvement over the last-month baseline is only **0.44%** on the later-month development test and is negligible on the new-household test. R² is not an accuracy percentage. A more complex model does not automatically improve prediction. The project's contribution includes uncertainty, explanation, careful evaluation, and an accessible deployment; do not describe the result as a large accuracy breakthrough.

The complete candidate scores, survey-context comparison, split counts and limitations are in [results/metrics.json](results/metrics.json). The saved model manifest records exact feature names, package versions and source-file hashes.

## Run locally

Use Python 3.12. From this project directory:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8012
```

Open http://127.0.0.1:8012 . The exported model is included, so serving does not retrain it. `/health` checks actual model loading. `/docs` provides interactive API documentation. Use **Load example** to demonstrate an illustrative request. After reproducing training locally, this control loads anonymous held-out observation histories generated by that run.

For Linux, activate the virtual environment and use the same Python commands. `startup.sh` runs Gunicorn with one worker for Azure's constrained free plan.

## Reproduce model training

```powershell
.\.venv\Scripts\python.exe data/download_data.py
.\.venv\Scripts\python.exe -m energy.train
.\.venv\Scripts\python.exe -m pytest -q
```

The 19-check suite requires the downloaded source files and generated per-household evaluation records. GitHub CI performs the download, training and checks without publishing those household-level files as artifacts.

The pipeline uses measured targets with six complete lag readings, retaining zeros. Missing targets are never manufactured. It keeps household IDs out of model features, reserves 20% of households, and uses chronological target-month splits. Selection and blend weights use validation only. Calibration determines interval width; test labels measure the frozen model. TreeSHAP contributions describe associations in the model, not causal energy use by each appliance.

See [notebooks/01_project_walkthrough.ipynb](notebooks/01_project_walkthrough.ipynb) for an explanation of the stages. The notebook runs the shared implementation instead of maintaining a conflicting copy of training logic.

## Data provenance and scope

[Data source notes](data/SOURCES.md) identify the original files, units and licence. The monthly file has 101,575 rows across 4,063 households and 25 monthly periods, October 2022–October 2024. Detailed survey context arrives later and is masked until known. The AC roster is a separate source module; it is not inferred from the general appliance list.

The interface supports historical forecast months from April 2023 through November 2024. November is a one-month extension beyond observed targets and has no measured outcome in this dataset. Predictions for 2026 or future operational use need refreshed data and validation. These records do not establish current tariff costs, measured appliance-level consumption or guaranteed savings. Prediction-interval coverage can change under temporal or population shifts.

## Azure deployment

[![Deploy to Azure](https://aka.ms/deploytoazurebutton)](https://portal.azure.com/#create/Microsoft.Template/uri/https%3A%2F%2Fraw.githubusercontent.com%2Fmanuka-rashen%2Flanka-energy%2Fmain%2Fdeployment%2Fazuredeploy.json)

The template creates only a Linux **F1 Free** App Service plan and a Python 3.12 web app, deploying the public `main` branch through manual Git integration. Choose a region permitted by your subscription and supporting Linux F1. It creates no paid database, storage account or monitoring service. Shared CPU limits and cold starts apply. If F1 is unavailable, do not silently select a paid plan; check another permitted region or explicitly approve a different plan.

The app resource location defaults to `centralindia`. In the portal, choose **Central India** for the resource-group region and keep the **Location** parameter as the explicit code `centralindia`. Check your subscription's allowed-region policy before using another location. A literal expression entered as a Location parameter can be rejected by that policy.

Verify the deployed URL, `/health`, and a real `/api/forecast` request before calling deployment successful. Resource creation alone is not proof that the trained model runs. Manual integration does not auto-deploy future commits; synchronize from Deployment Center after verified updates.

CI starts the committed model through `startup.sh` and verifies health, dashboard, metadata and a real HTTP forecast before downloading data and retraining. The committed metrics describe the frozen Windows-trained model. The Linux CI refit selected a history-only blend with 17.686 kWh test MAE in the first run; these temporary CI artifacts are not published or deployed. Platform-dependent numerical differences can change the winning validation candidate when performance is close. Use the committed model for the published demo and record the environment when reporting a new training run.
